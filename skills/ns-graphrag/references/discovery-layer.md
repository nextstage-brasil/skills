# Discovery layer (opt-in)

Investigative analytics **outside** the six answer shapes. Never a pipeline stage. Never gates answering.

## Gate

Enable only when product declares an archetype the six shapes cannot serve, for example:

- Enumerate indirect links under a hop cap with cited paths
- Group densely connected entities for analyst review
- Prominence / centrality for a declared screen
- Recurring patterns, inconsistency flags, coverage gaps

If every production question maps to unit, path, filtered set, count, synthesis, or document correlation — **keep discovery off**.

## Hard rules

- Traverse **fact edges only** (exclude pending_review, proposals, DERIVED).
- Every finding carries **paths and evidence** — same cite-or-refuse discipline.
- Findings are **hypotheses for human validation** — never written back as edges.
- Density and extraction quality are the levers — not algorithm knob tuning.
- Visualization shows cited subgraph or path — not the full graph (`references/query-modes.md`).

## Density caveat

Sparse graphs yield singleton groups; fully connected graphs yield one blob. Fix ontology, extraction, and confidence floors before changing grouping parameters.

## Recompute

Refresh when ontology, extract policy, or fact-edge set changes materially. Incremental ingest refreshes affected neighborhoods when the graph is large — not necessarily full recomputation every document.

## Anti-pattern

Running hierarchical modularity **clustering** on every ingest “for ops health” when no discovery archetype is declared. That is clustering-as-stage bias — refuse.
