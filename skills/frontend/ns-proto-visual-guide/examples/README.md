# Canonical examples

One level from [SKILL.md](../SKILL.md). Before drafting a normative guide, **read the specimen of the same surface type** and mirror tone, sections, and density.

## Map by surface type

| Type | Specimen | Shows |
|------|----------|-------|
| Canvas card | [card-canvas.md](card-canvas.md) | Zones, RO body, chips, footer, handles, edit vs follow-along |
| Panel form | [form-panel.md](form-panel.md) | Block order, toggles, empty states, modes |
| Shell | [shell-panel.md](shell-panel.md) | Fixed panel chrome — no per-selection fields |

## Suggested file names

| File pattern | Surface |
|--------------|---------|
| `*-card-visual.md` or `*-node-visual.md` | Canvas card |
| `*-panel-visual.md` or `*-painel-visual.md` | Side-panel form |
| `*-shell.md` or `*-appearance.md` | Panel shell |
| `layout-*.md` | Technical layout (grid, dimensions) |

Adapt names to the project. Keep surfaces in separate files and cross-link them.

## Publish checklist

- [ ] Entry in the project docs index
- [ ] Cross-links on sibling docs (card ↔ panel ↔ layout)
- [ ] **Does not cover** points at docs that own the excluded scope
