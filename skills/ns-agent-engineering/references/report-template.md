# Final report template

## Phase 1 — On-screen summary (chat only)

After the interview, post a concise recommendation in the conversation **before** writing any file:

- **Length:** ~150–200 words (hard cap — objective, no filler)
- **Content:** locked adaptation path, agent vs explicit non-agent decision, main trade-off, top risk (compounding errors / write tools), MVP scope hint, next handoff
- **Do not** include full tool tables or interview record in this summary

Then write the living design doc to **`docs/specs/agent-design.md`** (create `docs/specs/` if missing). Do not ask for a path. Do not write `docs/specs/agent-architecture.md` (that file belongs to `ns-multi-agent-architect`). Missing: create. Exists: update current-state sections; append Changelog + this Interview Record session. Never blind-replace.

## Phase 2 — Full report file (design handoff)

The file must be **self-contained**: a reader who never saw the interview can understand the adaptation decisions. Include every question asked, the recommended answer offered, the user's actual reply, and the locked decision derived from it. Also include the user's initial unprompted context.

Write the complete report to `docs/specs/agent-design.md` using the **section schema** below. The English headings in this template are the schema for the agent — **the written file** translates every heading, table header, and cell to the human's locked language (Language rule in `SKILL.md`), **except** doctrine labels (Evaluation, Prompt, RAG, Agent, Fine-Tune, Tools, Planning, Memory, Guardrails, Observability): they stay English as decision ids. Fill every **applicable** section — no placeholder text. If Agent was rejected, still include **Agent justification** with the explicit non-agent decision; omit or thin Tool / Planning / Memory / agent-metric sections that do not apply — do not write "N/A" stubs.
