## Problem statement

Build a system that answers employee FAQs using an internal wiki and HR PDFs. The requester initially asked for “an agent so it can be smart.” Scope is natural-language HR/policy Q&A with answers grounded in that private corpus. Constraints from the interview: no multi-step tool-acting Agent; no frameworks or implementation in this design; English as the locked product language.

## Evaluation criteria

**Done** means functional correctness on FAQ answers:

1. Every factual claim in the answer is supported by retrieved wiki or HR PDF passages.
2. Citations point to those supporting passages (title/section or equivalent locator).
3. When retrieval is empty or irrelevant, the system refuses or states that the corpus does not cover the question — no invented policy.

**Usefulness threshold:** ≥85% of a maintained golden FAQ set passes a groundedness + citation rubric (binary functional checks preferred; graded rubric only for open-ended phrasing quality).

**Business link (optional):** reduction in HR tickets for repeat policy questions (deflection), tracked after MVP if ticket data exists. Evaluation is locked before adaptation; success is not “sounds smart.”

## Failure diagnosis (info vs behavior)

**Type: information.**

Evidence: HR policies, benefits numbers, and wiki procedures are private and change over time. A general model can produce fluent HR-like prose but will invent leave days, stipends, or eligibility without the corpus. Behavior/format failures (tone, instruction-following) are not the primary gap once excerpts are in context.

Implication: close the gap with RAG after Prompt; do not treat this as an Agent or Fine-Tune-first problem.

## Adaptation path (locked ladder decisions)

| Gate | Decision | Rationale |
| ---- | -------- | --------- |
| Evaluation | locked | Groundedness + citations + refuse-if-unsupported; ≥85% golden FAQ pass |
| Prompt | yes — start | In-context grounded Q&A, citation format, refuse-if-unsure |
| RAG | yes — required | Information failure: private wiki + HR PDFs must be retrieved at query time |
| Agent | rejected | FAQ-over-docs needs passive retrieval + generation, not perceive/decide/write-act loops |
| Fine-Tune | deferred | No behavior-based failure evidence after Prompt + RAG; revisit only if format/tone still fails |

## Agent justification (or explicit non-agent decision)

**Explicit non-agent.** Adaptation ladder and “When NOT to Agent” both map FAQ / doc Q&A to Prompt + RAG. The end-to-end journey is one retrieve-then-generate path. There is no requirement to act on the environment with tools beyond passive knowledge retrieval, no write side effects, and no outcome-learning loop that would justify Agent complexity. Compounding multi-step error would hurt reliability on policy answers without improving Evaluation criteria. “Smart” is grounded retrieval quality + Prompt discipline, not Agent topology.

## Memory design

| Tier | What stored | Why |
| ---- | ----------- | --- |
| Internal weights | General language and instruction-following only | No Fine-Tune in MVP; do not encode volatile HR policy in weights |
| Context window (short-term) | Current question, retrieved passages, Prompt instructions, draft answer | Working state for one FAQ turn |
| External (long-term / RAG) | Indexed internal wiki pages and HR PDF chunks (durable product facts) | Sole source of policy truth; freshness via corpus updates |

## Evaluation plan (baseline metrics)

Agent-specific metrics (valid plan %, planning vs tool failure split) do not apply. Measure the Prompt + RAG baseline against locked Evaluation:

- Golden FAQ task success / rubric pass rate (target ≥85%)
- Citation presence and correctness rate
- Refuse rate on intentionally unsupported questions (should refuse, not invent)
- Cost and latency per query vs a no-retrieval Prompt-only baseline (Agent not required to “beat” anything; RAG must beat Prompt-only on groundedness)
- Failure logging: retrieval miss vs generation hallucination with retrieval present (separate root causes)

## Guardrails & observability

**Input Guardrails:** reject jailbreak / off-policy instruction overrides that try to bypass corpus grounding; limit bulk PII dumps in the question field where feasible.

**Output Guardrails:** answers that make policy claims must include citations tied to retrieved passages; block or regenerate unsourced policy assertions; prefer explicit “not in corpus” over speculative HR advice.

**Observability (MTTD/MTTR):** log query text (or redacted form), retrieved chunk identifiers, model answer, refuse flag, and groundedness/citation check outcomes. Use logs to distinguish ranking/retrieval failures from generation failures. Aim for fast detection when golden-set or production refuse/hallucination rates spike.

## Risks (compounding errors, write tools)

| Risk | Mitigation |
| ---- | ---------- |
| Hallucinated HR policy when retrieval misses or ranks poorly | Refuse-if-unsupported; citation checks; improve corpus coverage/ranking before any Agent idea |
| Stale wiki/PDF after policy change | Treat external store as source of truth; refresh index on doc updates; Evaluation includes freshness-sensitive goldens |
| Over-trust in fluent wrong answers | Rubric + output Guardrails; never ship without golden-set gate |
| Scope creep into write actions (tickets, email HR) | Out of MVP; any future Write tool needs HITL — not justified now |
| Compounding error from forced multi-step Agent | Already rejected; keep single retrieval + generate path |
